# Session: CFB Totals Deep Dive
Date: 2026-08-31
Project: NFL Betting Screener
Goal: Following the NFL totals deep dive earlier this session, Bradley asked for the same kind of investigation into CFB totals — he'd noticed a similarly wide predicted-total range there, with some very intense edges, and wanted to know why (expecting it to be at least partly legitimate given CFB's wider talent-gap variance, but wanted it checked, not assumed).
Continuing from: 2026-08-31-totals-deep-dive.md (same day, same session)

## Work Log
- Built a walk-forward diagnostic mirroring the NFL one: predicted_total, market_total, actual_total, plus each team's rating-window games count, for all ~4,200 FBS-vs-FBS games 2019-2024.
- Hit a real cfbd (collegefootballdata.com) API outage mid-investigation (Cloudflare 502s) — genuinely external, confirmed by retrying and having it clear on its own after ~10-15 minutes. Not our bug, but see below for what it exposed.
- **First diagnostic run surfaced something worse than expected**: several exact-duplicate predicted totals (86.7, 87.7) recurring identically across completely different seasons for the same matchups (e.g. West Virginia @ Oklahoma State: 86.7 in 2020, 2022, AND 2024). Pulled the underlying off/def ratings and found Oklahoma State's home rating was bit-for-bit identical (20.693585, 0.156399) across 34 games spanning six seasons.
- **Root cause**: Oklahoma State's actual game log only contained 12 games — all from 2017. Traced to `get_cfb_schedules` in `screener/fetch_cfb_stats.py`: the whole schedules dataframe returned only 2017 data despite requesting 2017-2024. The cfbd outage above had caused most years in a multi-year fetch loop to fail; since the function's `except Exception` handler treats any per-year failure as "not published yet yet" and just skips it, and since at least one year (2017) succeeded, the resulting PARTIAL dataset got cached (20-hour TTL) as if it were the complete, correct one. Every rating computed from that cache was then silently built from one frozen, years-stale season. Confirmed via the cache DB directly: the poisoned `cfb_schedules_2017-2018-...-2024` row's timestamp lined up exactly with when the outage-affected fetch ran. Found the identical bug pattern in `get_cfb_betting_lines` too (same silent-skip-then-cache-partial logic), just not triggered this time because *all* years happened to fail together there, which correctly raised instead of caching a partial result.
- **This is a forward-looking reliability bug, not a correction to trusted numbers**: this exact corruption only existed because tonight's diagnostic re-fetch collided with a real, transient outage — it wasn't a long-standing issue that had been silently corrupting the live pipeline before now. But the *mechanism* (a transient API hiccup + partial success + naive caching) could just as easily hit a real scheduled GitHub Actions run in the future, which is why it was worth fixing regardless of tonight's specific trigger.
- **Fixed** in `screener/fetch_cfb_stats.py`: added `_reject_stale_year_failures` — if any requested year that's fully in the past (not the current/upcoming season, where "not published yet" is legitimate) fails to fetch, raise instead of silently caching whatever partial data succeeded. Applied to both `get_cfb_schedules` and `get_cfb_betting_lines`. This raises a normal exception that the existing `run_cfb_game_screener` try/except + `send_partial_failure_alert` machinery (built in the 2026-08-24 reliability audit) will already catch and surface — no new alerting infrastructure needed, just closing the gap that let this specific failure mode bypass it.
- **Cleared the one poisoned cache row** (`data/cache.db`'s `cfb_schedules_2017-2018-...-2024` entry) after confirming with Bradley first, per the project's hard rule on cache deletion — a TTL cache row, rebuildable from the API, not ledger data.
- **Re-ran the diagnostic on the clean, complete data — confirmed the bug was the dominant cause**: extreme (20+ point) total edges dropped from 417 to 19 out of ~4,200 games (>20x reduction), the worst edge dropped from 47.7 to 32.3, and the exact-duplicate-prediction pattern vanished completely — every game in the new top-20 list is a distinct team/season, consistent with genuine variance rather than a stuck computation.
- **Re-ran the actual CFB backtest on the clean cache to make sure nothing else changed**: spread (2244 bets, 54.1% win rate, +3.3% ROI) and total (1426 bets, 48.9% win rate, -6.6% ROI) came back byte-for-byte identical to the already-documented numbers from the 2026-08-20 CFB build session — confirming this was a fresh corruption from tonight's outage, not something that had been quietly wrong in Bradley's trusted numbers all along.
- **Checked for a smaller, real (non-buggy) contributor**: pulled every game where either team had fewer than 10 games of rating history (30 of 4,226 — about 0.7%). Every single one involved a recent FCS-to-FBS transition program: James Madison (FBS since 2022), Sam Houston (2023), Jacksonville State (2023), Kennesaw State (2024) — some with as few as 1-2 games of real FBS history. This is a genuine, structural, small-scale version of the same "thin unregularized sample" issue behind the NFL relocation bug fixed earlier tonight, but it's not a bug here — these teams really do have almost no FBS-level data yet. Left unfixed (very low volume, same treatment as the NFL/CFB props model's small-sample edge scaling would be the natural fix if it ever becomes a real drag).
- **Confirmed the remaining width is real and expected, not a problem to fix**: even after excluding both factors above, CFB's predicted-total std dev (10.3) is still meaningfully wider than NFL's (~6.6) — and so is the *market's own* total line std dev (7.98 vs. NFL's ~4.46). The market itself prices CFB games with much more variance than NFL, consistent with the sport's real characteristics (bigger talent gaps across a 130+ team field, transfer-portal roster churn between seasons, pace/style differences). This directly validated Bradley's own expectation going in.

## Decisions made
- CFB totals' "no proven edge" conclusion is unchanged and was never actually wrong — the bug found tonight was a fresh, transient corruption, not a flaw in the existing documented backtest
- Did not attempt the same total+spread combined-conviction filter that gave NFL totals a real edge — flagged as a natural next step, not yet tested for CFB
- Did not build small-sample regularization for CFB's FCS-transition teams — real but very low-volume (0.7% of games), not worth the complexity yet
