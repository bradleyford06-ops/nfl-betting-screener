## Work Log
- Scoped with Bradley: FBS (Division I) college football spreads/totals model, own opponent-adjusted power rating (not SP+ itself), validated against SP+, full FBS scope (~134 teams incl. Group of 5), integrated into the same daily pipeline/dashboard/email as an independent strategy
- Bradley provided a free CollegeFootballData.com (cfbd) API key, saved to local `.env` as `CFBD_API_KEY` (gitignored, not yet added to GitHub Actions secrets — that's a later step pending his sign-off before touching the live production workflow)
- Researched and confirmed data feasibility: `cfbd` Python package (free w/ signup) provides FBS schedules, real historical betting lines (spread/total/moneyline by provider, includes final scores — no need to pay for The Odds API's historical endpoint), and SP+ ratings directly. The Odds API (already in use for NFL) already covers live NCAAF spreads/totals, same provider/plan
- Built `screener/fetch_cfb_stats.py`: schedules, betting lines, SP+ ratings, and a dynamically-built (not hand-typed) team name map for matching Odds API's "School Mascot" names to cfbd's "School"-only names
- Built `model/cfb_power_ratings.py`: reuses the NFL model's generic opponent-adjustment math (`build_team_games`) but with CFB-specific constants derived from real data (2017-2024): home-field advantage 4.0 pts (vs NFL's 1.5), margin std dev 21.0 pts (vs NFL's 13.5) — and a new FCS-opponent handling piece: since FCS opponents never get their own rating (cfbd only returns FBS-side games), they're treated as a fixed weak floor rating (derived from the real ~16pt scoring gap in FBS-vs-FCS games) instead of average, so a blowout win over an FCS team doesn't get misread as a mediocre result
- Validated our from-scratch ratings against SP+ for the 2023 season: 0.961 correlation on rating, 0.947 on rank — strong confirmation the model tracks a trusted public system closely, with the biggest disagreements concentrated in lower-tier/mid-major teams (plausible, since SP+ likely factors in recruiting/returning-production priors our results-only model doesn't use)
- Built `backtest/simulate_cfb.py` + `backtest/run_cfb_backtest.py --sweep`, walk-forward across 2019-2024 real historical FBS lines (4227 FBS-vs-FBS games). One important caveat: cfbd's historical lines don't include the actual spread/total price (unlike nfl_data_py), so backtest ROI assumes standard -110 odds — win rate is exact, ROI is an estimate
- **Spread: real edge found.** Even edge>=0 (no filter) won 52.6%/+0.4% ROI — stronger baseline than the NFL model shows. Best threshold: edge>=4.0 (2255 bets, 55.5% win rate, +5.9% ROI, +133.3 units — the best total profit of any threshold tested). Set as the live `SPREAD_EDGE_THRESHOLD` in `model/cfb_power_ratings.py`
- **Total: no edge — and actively gets worse with bigger disagreement** (49.6% at edge>=0 down to 41.5% at edge>=20), a worse pattern than the NFL total model (which is at least flat). Bradley asked me to investigate the cause before deciding rather than just disable or ship it speculative
- **Investigated and found a real bug, not just weak signal.** FCS opponents get a fixed placeholder rating (since they never earn a real one), but that placeholder never self-corrects the way two real FBS teams do against each other — so the ~830 FBS-vs-FCS games each season quietly dragged the *entire* FBS rating pool off-center as the iterative fit re-balanced around them (mean off_rating drifted to -5.0, mean def_rating to +8.4, should both be 0). Added twice per game (once per team), that inflated every predicted total by several points, worse for bigger disagreements — exactly the pattern seen. Confirmed this didn't touch spreads at all (a shared rating offset cancels out in a head-to-head comparison), which is exactly why spreads backtested clean while totals didn't
- **Fix applied** in `model/cfb_power_ratings.py`: re-center off/def ratings to true mean zero after each rating build, and compute the league scoring baseline only from real FBS-vs-FBS games (previously contaminated by FCS blowout scores). Re-ran the full backtest: spread numbers are byte-for-byte identical (2255 bets, 55.5%, +5.9% ROI — confirms the fix was surgical), and the total model's pathological "gets worse with bigger edge" pattern is gone — it's now flat around 47-52% across every threshold, same shape as the NFL total model's "no proven edge but not broken" result, not the same bug as before
- **Decision needed from Bradley:** CFB totals now match the NFL totals precedent exactly (flat, no edge, but no longer buggy) — options are to enable it the same way NFL totals are (live, labeled unproven/speculative) or leave it out of the CFB build. Bradley chose: keep live, labeled speculative, same as NFL
- Wired the model into the full pipeline: `screener/pipeline.py` (new `run_cfb_game_screener`, wrapped in a try/except so a CFB-side failure can never take down the NFL run — same lesson as the team-name-lookup crash from 2026-08-17), `screener/ledger.py` (via new `cfb_spread`/`cfb_total`/`cfb_total_speculative` strategy names, kept distinct from NFL's so season performance tracks them separately), `screener/reconcile.py` (routes each open pick to the right schedule — NFL vs CFB — based on its strategy prefix), `email_report/formatter.py` (new CFB section, reusing the existing game-flag formatter), and the dashboard (new "College Football" tab with its own week-pills, kept structurally separate from the NFL "weeks" data since CFB's Week 1 and NFL's Week 1 are different games on different dates — merging them would have been confusing)
- **Found and fixed two real production-path bugs during end-to-end testing** (before ever touching the live ledger/dashboard):
  1. `get_current_week`-equivalent for CFB was getting fooled by one leftover 2024 game (App State @ Liberty, likely hurricane-postponed and never marked final in cfbd's data) into reporting a stale week from a season that was long over. Fixed by scoping the "nearest unplayed week" search to only the most recent season in the data (`get_cfb_current_week` in pipeline.py)
  2. Team-name matching between The Odds API and cfbd was silently dropping real FBS teams whose names disagree on accents/punctuation (San José State vs San Jose State, Hawai'i vs Hawaii, Ragin' Cajuns vs Ragin Cajuns) — fixed by normalizing both sides (strip accents/apostrophes, lowercase) before matching, more scalable than a hand-typed override list across ~134 teams
- **Found and fixed a deeper version of the earlier FCS-contamination bug.** The first fix (re-centering ratings to mean zero) treated the symptom, not the cause — live testing then showed obviously-wrong predictions (Northwestern favored by 50 over FCS South Dakota State). Root cause: FCS opponents were getting their own real rating computed from just their one game against an FBS team, and — critically — that bogus rating was then actually being *used* (a normal dict lookup matched before the intended `.fillna()` fixed-floor fallback ever got a chance to fire) whenever an FBS team's own rating was adjusted for having played them. This meant the calibrated FCS floor was essentially never being applied in practice. Fixed by explicitly filtering to the real FBS team set before any rating is computed at all (`ratings_from_cfb_team_games` now takes an explicit `fbs_teams` set)
- **Backtest re-run after the real fix — spread edge is real but a bit more modest than first reported:** 2244 bets, 54.1% win rate, +3.3% ROI at the 4.0 threshold (down from the earlier, bug-inflated 55.5%/+5.9%, but still a solid, evidence-backed edge — not perfectly monotonic across the sweep, edge>=8 dips slightly negative, likely noise given ~4,200 total games). Total: still no edge either way (48.9% at threshold 6.0), consistent with both the buggy and fixed versions
- Verified end-to-end against real 2026 week 1 data after all fixes: CFB screening correctly resolves "2026 week 1," FCS opponents (Albany, Citadel, etc.) are correctly and silently skipped, real FBS teams (San José State, Hawai'i, Louisiana) are correctly matched, and predictions look sane (e.g. Rutgers by 44 over UMass, a real but not absurd mismatch) — 27 CFB spread picks and 19 speculative total picks flagged, NFL side unaffected (still 9 picks)
- Deliberately tested via a standalone script calling `run_screener()` directly rather than running the real `main.py`, specifically to avoid writing test picks into the permanent ledger (`data/ledger.db`, tracked in git) or overwriting the live dashboard before Bradley had reviewed anything
